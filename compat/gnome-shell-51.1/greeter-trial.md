# Испытание отпечатка на начальном экране GDM 51.1

Позднее на моковом провайдере зафиксирован успешный вход через
`gdm-fingerprint`; [журнал пробы](../../docs/evidence/gnome-shell-51.1/README.md).
Он подтверждает этот отдельный сценарий, но не устраняет остальные ограничения
исследовательской правки.

Штатный GNOME Shell 51.1 не подключает fingerprint manager для начального
greeter: это сделано upstream намеренно. Патч
`greeter-fingerprint-trial.patch` снимает только этот запрет и отдельно
запрещает запуск fingerprint без выбранного имени пользователя. Он не меняет
парольный механизм, но вход без пароля может оставить связку ключей GNOME
закрытой. Это **испытание**, а не подтверждённая поддержка первичного GDM.

Патч применим только к `authServicesLegacy.js` со штатной суммой
`3b0c729d4993f2d41e19f7a5e7b6436b7bf0226fec84f75929679934ee9d9952`;
сумма результата —
`2291c735682a0612da6613d7468696e6a3d00cb93ed37e8f359081d8c283abf7`.
Для проверки использован stock-ресурс планшета и методы логина: после выбора
пользователя `loginDialog.js` вызывает `begin({userName, hold})`. Тест
`test-greeter-fingerprint.cjs` проверяет подключение менеджера, запрет
отпечатка без имени и сохранение парольного пути. Те же методы проверены в
отдельном процессе GJS на планшете; реальный greeter ими не испытывался.

Для независимой временной пробы применяют `G_RESOURCE_OVERLAYS` только в
drop-in экземпляра `/etc/systemd/user/org.gnome.Shell@gdm.service.d/`, а не
шаблона `org.gnome.Shell@.service.d/`. Каталог в `/run` должен содержать
отдельные проверенные файлы `userVerifier.js`, `authServices.js` и
`authServicesLegacy.js`; первые два — исследуемый generation-патч с теми же
ограничениями, что и в `README.md`. Проверить точную версию и исходные хеши
перед использованием; нельзя подсовывать файлы от GNOME 51.1 другой версии.
Новая переменная вступает в силу только у нового процесса greeter; действующую
сессию пользователя принудительно не завершать. Удаление drop-in и повторный
старт greeter отменяют подмену; файлы в `/run` исчезают после перезагрузки.

PAM-сценарий `gdm-fingerprint`, политика и работающий fprintd-адаптер должны
быть настроены отдельно. Наличие доступного устройства не подтверждает
работоспособность GDM, а успешный программный mock не подтверждает работу
сенсора. В предыдущих пробах на локскрине дважды терялась сессия, поэтому
использовать журналирование и сохранить парольный вход.
