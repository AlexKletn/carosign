# Исследование отмены GDM в GNOME Shell 51.1

**Исправление причины сбоя не подтверждено. Патч нельзя устанавливать.**

Гипотеза об одной лишь реэнтрантной доставке `Reset` не подтвердилась в
испытании с настоящей D-Bus и разными object path: обе версии завершились одной
отменой без петли. На планшете `libgdm` создаёт новый peer-to-peer
`GDBusConnection` для каждого запроса повторной аутентификации; равенство
механизма в этих условиях ещё требуется проверить.

Исследуемые upstream-файлы GNOME Shell 51.1 `userVerifier.js`,
`authServicesLegacy.js`, `authPrompt.js`, `fingerprintManager.js` побайтно
совпали с ресурсами установленного на планшете `libshell-51.so`. Отпечаток
на планшете оставлен отключённым до установления и проверки причины.

`generation-limited-open.patch` — **экспериментальный** вариант:
он сериализует только открытие proxy и расширений libgdm, проверяет поколение
после ожиданий, отменяет ожидающие вызовы сервисов и гарантирует завершение
`hold`. Ожидание открытия ограничено пятью секундами, но барьер остаётся до
фактического ответа старого открытия: отмена GIO завершает ожидание клиента,
не гарантируя остановки серверного метода. При бесконечно зависшем старом
вызове новые открытия завершаются по сроку и не возобновляются автоматически.

Модельные проверки в `tools/gnome-generation-candidate-repro.js` охватывают
перекрытие A/B/C, отмену вызова сервиса, поздний ответ/ошибку и сроки; опыт
`tools/gio-cancel-inflight-repro.js` на отдельной D-Bus демонстрирует, что
отменённая клиентом работа может продолжаться на сервере. Кандидат **не**
подтверждает завершения серверного `BeginVerification` после отмены, и
бесконечный цикл планшета им не воспроизведён. Это не проверенное исправление;
его нельзя устанавливать вместо штатного GNOME Shell на основании этих тестов.
