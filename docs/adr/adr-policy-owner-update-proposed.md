# Проект ADR: обновление политики через владельца допусков

Статус: предложение, не разрешает production-запуск.

Независимый установщик должен изменять политику без гонки между записью и
выдачей разрешения работнику. Уведомление inotify само по себе не упорядочивает
внешнюю запись с отправкой разрешения. Поэтому системный владелец политики
должен быть единственным субъектом, имеющим право записи в её хранилище, а
установщик должен передавать ему проверяемое предложение обновления по
контрольному каналу. Наличие root или владельца namespace, способного обойти
разграничение, входит в модель доверенной администрации, а не устраняется
наблюдателем файлов.

До принятия решения требуется определить: системный источник и проверку
полномочий подключённого установщика, защиту хранилища от других писателей,
проверку происхождения и содержимого обновления, а также восстановление после
сбоя и расположение контрольного канала. UID, SO_PEERCRED, путь сокета и факт
открытия файла сами по себе не подтверждают полномочий. Отсутствие любого из
этих условий закрывает production-подключение.

Внутреннее испытание использует ограниченное сообщение с длиной, данными и
ответом с поколением. Это опытный формат, не публичный wire и не утверждённая
часть спецификации. Владелец отзывает прежние разрешения до записи и публикует
новое поколение только после проверки нового наблюдаемого снимка. Ошибка
после отзыва оставляет владельца закрытым. Потеря ответа не означает, что
запись не произошла; повтор без сверки результата не допускается.
