# Нумерация пропуска истории и снимка

**Статус: предложение; не принято и не подключено.** Документы 07 и 13
требуют явно сообщать об утраченной истории и выдавать авторизованный снимок,
но не определяют номер синтетического `EVENT_GAP` и курсор после перезапуска.
Действующий код намеренно отказывает в кодировании пропуска.

## Предлагаемый порядок для одного запуска

Пусть `A` — последний номер, подтверждённый клиентом при подписке, а `L` —
последний номер истории в момент атомарного снимка (`A < L`). Предлагается:

1. После авторизации наблюдателя собрать состояние и `L` как один снимок;
   терминальный итог мутации прочитать из устойчивого источника.
2. Отправить синтетический `EVENT_GAP` с `sequence = A + 1`,
   `gap_after_sequence = A` и полным снимком с `last_event_sequence = L`.
   Этот номер не добавляется в историю операции и относится только к ответу
   конкретного наблюдателя. Выдача снимка внутри события требует подтвердить,
   что это удовлетворяет требованию документа 07 о снимке после пропуска.
3. Клиент проверяет идентификаторы, номер и снимок, атомарно применяет снимок
   и продолжает с `L + 1`. Номера между `A + 1` и `L` не воспроизводятся.
   При терминальном снимке или `L = u64::MAX` продолжение не вычисляется;
   неконсистентный нетерминальный снимок на предельном номере отклоняется.
4. Повторная авторизация и проверка срока требуются при выдаче; потеря
   соединения или неопределённый исход отправки не подтверждает доставку.

Это изменение семантики публичных кадров требует отдельного рассмотрения N-05.
Альтернатива — два кадра, `EVENT_GAP` и отдельный `OperationSnapshot`, с
явным правилом сопоставления. Нельзя переходить на один из вариантов только
по наличию поля `snapshot` в protobuf: нужны проверки независимых клиентов.

## Перезапуск

Журнал завершённой мутации сохраняет исход, но не курсор событий текущего
запуска. Нельзя восстанавливать его из нуля или считать прежний `L` доказанным.
Нужен отдельный договор идентичности запуска потока и ответ авторизованному
`GetOperation` из устойчивого состояния. До решения повтор по старому
курсору остаётся закрытым. Это не требует миграции дорелизной базы v3.

## Необходимые проверки

Испытать две реализации клиента, настоящие сокеты, переполнение кольца,
снимок терминальной и нетерминальной операции, конкурентную публикацию,
потерю отправителя между кадрами, отзыв и отключение наблюдателя,
`A = u64::MAX`, `L = u64::MAX`, повреждённые ID и несогласованные номера.
Для мутаций отдельно доказать происхождение исхода из устойчивого журнала;
один терминальный маркер в памяти таким доказательством не является.
