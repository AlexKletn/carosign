# 12 — Заголовок кадра Goodix: поля и смещения

Сводка по двум источникам: proba ✅SRC (её поля подписаны именами) и
`goodix.rs` ✅SRC (перенос из двоичного HAL). Это самый часто нужный кусок —
по нему собирается любой кадр.

## Заголовок команды (128 байт, `SEND_MODFD_CMD`)

| смещение | поле | смысл |
|---|---|---|
| `+0` | — | для Goodix с телом: **физический адрес тела, 32 бита** (старшая половина — флаги, не трогать) ✅SRC |
| `+4` | — | флаги, при 32-битном адресе не менять ✅SRC |
| `+32` | `команда` (`cmd_id`) | `1000`, `1001`, `1016`, `1086`, `1111`, … ✅SRC |
| `+36` | `DLINA` | объявленная длина тела; шим поднимает до `0x4FFA8` ✅SRC |
| `+?` | `группа` | группа приложения ✅SRC |
| `+?` | `счётчик` | номер команды в сеансе (растёт) ✅SRC |
| `+?` | `время` | `ktime_get_real_seconds()*1000`, 64 бита ✅SRC |
| `+?` | `свалка`, `журнал`, `шифр` | отладочные поля ✅SRC |
| `+?` | `длина_тела` | фактическая длина тела ✅SRC |

⚠️ Точные числовые смещения полей (кроме `+32`, `+36`, `+0`, `+4`) proba
держит под именами `GF_POLE_*` — читать их там же, в
`spinel_fp_proba.c` (`GF_POLE_TELO`, `GF_POLE_SHIFR`, `GF_POLE_ZHURNAL`,
`GF_POLE_SCHET`, `GF_POLE_GRUPPA`, `GF_POLE_VREMYA`, `GF_POLE_SVALKA`,
`GF_POLE_KOMANDA`, `GF_POLE_DLINA`).

## Ответ (64 байта)

| смещение | поле | смысл |
|---|---|---|
| `+0` | результат | код команды; `1006` — несовпадение ✅BIN |
| `+4` | статус канала | ошибка транспорта, отдельно от результата ✅BIN |

## Тело события `1016` (`0x4FFA8`)

| смещение | поле |
|---|---|
| `+0x4FD65` | `0x02000000` при старте |
| `+0x4FD94` | `0x200` |
| `+96` | маска событий |
| `+100` | операция |
| `+0x4FF9C` | ступень (`1` старт, `2` начальная, `4`, `5`) |

## Правило

Числа держать **именованными** и в одном месте на слой: Rust —
`goodix.rs`; ядро — `GF_POLE_*`. Голых чисел в договоре не бывает
(`AGENTS.md`, «Число в договоре обязано иметь имя»).
