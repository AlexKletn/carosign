# 21 — Сток: поворот жеста и служебные команды прошивки

## 21.1 `gf_hal_nav_code_convert` @`0x1199f0` — жест с учётом поворота ✅BIN

Вход: код жеста от датчика. Выход: код после поворота, в `*param_2`.

```
g_orientation = DAT_00518138   (0, 0x5a, 0xb4, 0x10e)
g_facing      = DAT_0051813a   (0 или не 0)

если код ∈ {7, 8, 9, 10}      → без перевода (служебные)
иначе если g_orientation == 0      → без перевода
иначе если g_orientation == 0x5a (90°):
    3→6, 6→4, 4→5, 5→3
иначе если g_orientation == 0xb4 (180°):
    3→4, 6→5, 4→3, 5→6
иначе если g_orientation == 0x10e (270°):
    3→5, 6→3, 4→6, 5→4
затем, если g_facing == 0:  5→6, 6→5   (обратная сторона — своп)
```

⚠️ Четыре кода `{3, 4, 5, 6}` — это четыре направления; своп при
`g_facing == 0` означает, что датчик на обратной стороне. Это открывает
пункт из «чего нет»: **поворот жеста описан целиком**, а значение
ориентации придёт от системы (Android `set_orientation`).

## 21.2 Служебные команды прошивки ✅BIN

| функция | команда | тело | смысл |
|---|---|---|---|
| `gf_hal_download_fw` @`0x119dd0` | `1003 DOWNLOAD_FW` | 96 | заливка прошивки датчика |
| `gf_hal_download_cfg` @`0x119e5c` | `1004 DOWNLOAD_CFG` | 96 | настройки из `fw_cfg` |
| `gf_hal_post_enroll` @`0x11d390` | `1008 POST_ENROLL` | 96 | конец записи |
| `gf_hal_create_and_set_esd_timer` @`0x119ee8` | — | — | таймер проверки ESD |

⚠️ Тела у трёх команд — **все по 96 байт и нулевые**: их содержимое
готовит приложение, а не HAL. Это надо знать, чтобы не искать «забытые
поля».

## 21.3 Проверка ESD ✅BIN

`gf_hal_create_and_set_esd_timer`: создаёт таймер, ставит срок из
`g_hal_config` , по наступлении — проверка (`1019 ESD_CHECK`, тело 100,
`FUN_00119fc8`). Смысл: если датчик «выпал» (электростатический разряд),
HAL **перезапускает** его (`reset` + повтор загрузки `fw_cfg`), а не бросает.

⚠️ В нашем C этого нет: у нас датчик может «залипнуть» до перезагрузки,
и это могло быть одной из причин «ошибка 2» и «нет событий».

## 21.4 Что теперь закрыто из списка «чего нет»

* раскладка `uidev` для `uinput` — [20](20-nav-i-uinput.md);
* тела `1071`/`1073` — там же;
* поворот жеста — раздел 21.1 здесь;
* `1003`/`1004`/`1008` — тела по 96 байт, нулевые (раздел 21.2).

## 21.5 Что осталось

1. Значения `g_hal_config[0x3c]`/`[0x40]` (интервалы навигации) на нашем
   датчике — читаются из ответа `1001`, в коде только пределы.
2. Таблица `gf_strnav` (имена кодов навигации) — строки пусты, как и у
   остальных таблиц.
3. `1064` / `1102` / `1103` как **операторы** (не команды) — что датчик
   вкладывает в `+104` при обычном распознавании, проверено только
   косвенно (в аудите замечено, что поле читается).
