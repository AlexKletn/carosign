# 16 — Полная последовательность HAL по декомпиляции

Всё ниже — «что делать по порядку». Каждый шаг с адресом функции, из
которой прочитан ✅BIN. Это то, что Rust обязан повторить **и** чем проверять
себя, когда «не идёт».

## Открытие (`gf_hal_open` → `hal_milan_an_series_init` @`0x15da10`)

| шаг | вызов | тело | из чего |
|---|---|---|---|
| 1 | `GF_IOC_ENABLE_POWER` (0x6707) | — | `gf_hal_device_open` @`0x1369d0` + probe |
| 2 | `GF_IOC_GET_FW_INFO` | 1 байт | там же |
| 3 | `GF_IOC_RESET` (0x6702) | — | там же |
| 4 | `DETECT_SENSOR` (1000) | 544 | `@0x15da10` |
| 5 | `INIT` (1001) | 344, `+0x60` — байт прошивки, `+0x8c` — кеш OTP | там же |
| 5a | если ответ `0x405` — повторная загрузка `fw_cfg` (`FUN_0015f78c`: до 3 попыток `RESET` + `1003`) | | там же |
| 6 | **разбор ответа `1001`:** `+100` `sensor_row`, `+0x68` `sensor_col`, `+0x74` `nav_row`, `+0x78` `nav_col`, `+0x62` `esd_check_flag`, `+0x7c` байт для `chip_info` | | там же |
| 7 | `GF_IOC_ENABLE_IRQ` (0x6703) через `gf_hal_device_enable` | — | там же |
| 8 | `INIT_FINISHED` (1005) | 100 | `gf_hal_init_finished` @`0x11b7bc` |
| 9 | `IRQ` (1016) — ступень `2`, при выключенном IRQ (если `g_hal_config[0xd0] ≠ 0`) | `0x4ffa8` | `FUN_00160ae0` @`0x160ae0` |

⚠️ В нашем Rust шаги 4–9 есть, но **шаг 5a нет** (повтор после `0x405`) и
**шаг 6 не разбирается** (следствие: `spi_speed` и `esd` не ведутся).

## Что стоит закрыть в Rust (по убыванию важности)

1. **Запись отпечатка**: `1006` → `1007` → по событиям → `1012` → `1008`.
   Сейчас её нет вовсе — а без шаблона распознавать нечего.
2. Пошаговая проверка `1001`: разбор полей ответа, которые HAL кладёт в
   глобальные (строки, столбцы, `esd`), — иначе `spi_speed` и ESD не ведутся.
3. Повтор `fw_cfg` при `0x405` (шаг 5a открытия).
