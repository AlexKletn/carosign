# 03 — Ядро: слушатель TZ

Файлы: `linux-rom/fingerprint/listener/spinel_qsee_listener.c` (389 строк) и
`listener-state.h` ✅SRC. Плюс правки `qcom_scm` в дереве ядра.
Назначение: когда TZ в ответ на команду хочет файл (FS, GPFS) или байты из
RPMB, она возвращает `BLOCKED_ON_LISTENER` / `INCOMPLETE`; ядро должно разбудить
службу, дождаться ответа и продолжить вызов.

## Регистрация

* Три службы: **FS** `listener_id=10` (`0xa`), **RPMB** `0x2000`,
  **GPFS** `0x7000`.
* Буферы: FS и RPMB — 32 КБ, GPFS — 504 КБ (`SPINEL_GPFS_BUF`), из того же
  пула `qcom_tzmem` с мостом.
* `REGISTER` — SMC `0x32000206` (owner QSEE_OS 50, svc 2, cmd 6), args
  `{id, phys(RW), size}`; `DEREGISTER` — `0x32000202`; `CONTINUE` —
  `0x320000fc` с буфером (подкоманда + `listener-response`).
* ✅SRC Владельца схема: **демон (userspace) работает с копией** буфера
  (`shadow`), в буфер TZ пишет только ядро. Это и есть защита от гонок.

## Машина состояний (`listener-state.h`) ✅SRC

```
IDLE ──START──▶ WAITING ──DONE──▶ ANSWERED ──CONSUME──▶ IDLE
                   └────ABORT────▶ POISONED   (до перезагрузки)
```

* `START` принимается только из `IDLE` — второй запрос при занятом слушателе
  получает `-EIO`.
* `ABORT` (срок 5 с или закрытие демона) переводит в `POISONED`: запоздалый
  ответ не путается с новым.
* `open` демона — `atomic_cmpxchg`: один демон, второй получает `-EBUSY`.

## Проводник ↔ демон

* `read(/dev/spinel-lstnr)` отдаёт **4-байтный номер** службы (FS/RPMB/GPFS) —
  по нему демон выбирает буфер.
* Демон видит буфер **через mmap** (смещение страницы — RPMB, две — GPFS).
* Ответ — `ioctl(_IOW('L', 1, int), ret)`; ядро копирует `shadow` обратно в
  буфер TZ и возвращает `ret` в `qcom_scm` для продолжения.

## Поведение стока, которое мы воспроизвели ✅BIN

* Неизвестный ID: сток ставит статус `0xffffffff` и кладёт его в ответ
  (`0x7e237c–0x7e2388`, `0x7e212c–0x7e2154`). Было: пустое продолжение `0xfc`.
* Занятый слушатель: сток ждёт освобождения (`0x7df77c–0x7df844`). Было:
  продолжение сразу.
* Кэш/flush до и после `CONTINUE` — обязательны.

## Требования к Rust-службе слушателей

1. Открыть `/dev/spinel-lstnr` (единственный владелец), `mmap` всех трёх
   буферов, `poll`/`read` номера службы.
2. Обслужить и ответить `DONE(ret)` **не позже 5 с** — иначе слушатель
   «отравлен» до перезагрузки.
3. Не писать в буфер TZ напрямую: только в свою копию, ответ ядро заберёт.
