# 07 — HAL стока: состояния и команды (`libgf_hal.so`)

Эталон, который обязан уметь Rust. Источники: ✅BIN `libgf_hal.so` (адреса),
✅MSR замеры, ✅SRC перенос в `goodix.rs`/`irq.rs`/`authentication.rs`.
Полная декомпиляция — задача отдельным заходом (см.
[11](11-otkrytye.md)); ниже то, что уже читается уверенно.

## Дерево вызовов

```
gf_hal_open(notify)
  → gpio/питание через driver ioctl (GF_IOC_ENABLE_POWER, GET_FW_INFO, RESET)
  → gf_hal_device_enable / gf_hal_set_active_group
gf_hal_authenticate(dev, challenge, flags)
  → мьютекс, проверка «устройство готово»
  → таблица устройства +64 или +112  (gf_hal_irq)
  → gf_hal_common_authenticate → libgf_ca_invoke_command(1010)
```

## Замок «одно событие за раз» ✅BIN

* Общий мьютекс берётся в `gf_hal_irq` (`@0x18174`) и в `gf_hal_authenticate`
  (`@0x17240`).
* Слово по `g_fingerprint_device[+0]` (через `d0000+3568`, смещение
  `#3344` — это сама блокировка, `#3568` — признак готовности) ✅BIN.
  Ноль → `gf_hal_irq` сразу возвращает `1010` (`0x3f2`) без вызова; то же
  делает `gf_hal_authenticate` (`@0x172e8–0x17314`).
* `gf_hal_irq` зовёт `+112`, `gf_hal_authenticate` — `+64`, из таблицы
  устройства (`[x8, #3504]`).

✅MSR **Следствие:** и сток, и наш Rust обрабатывают ровно **одно событие на
один край**. Серии внутри одного `1016` не бывает ни у кого. Если край
пришёл — обрабатывайте и снова ждите; не «продолжайте» по шагу.

## Разбор ответа события ✅BIN (`irq.rs`)

* `+96` (u32) — **маска**, какие ветви отработать: бит 1 `0x2`, бит 7 `0x80`,
  бит 2 `0x4`.
* `+100` (u32) — **операция**: `0` запись, `1` распознавание, `2` быстрое
  распознавание, `4` FIDO, остальное — `Other`.
* Главный обработчик (`@0x5fa20–0x5fb48`) берёт `операция − 4` и прыгает по
  таблице `@0xa8a18`; при `0…4` (операции `4…8`): `4` — таймер
  (`create_timer` @`0x15ac0`, `set_timer` @`0x149f0`, арг `2`, срок 0),
  `6` — `notify_acquired_info(6)`, `7` — `notify_acquired_info(0)`;
  всё прочее — **ничего**.
* Флаги «вид команды совпал» для `1064`, `1102`, `1103` пишутся по
  `@0x5f8cc–0x5f948`.
* `1006` в ответе — несовпадение **только** на ветке завершения
  распознавания (`@0x5fb04–0x5fb10`, `@0x5fee0–0x5fef0`), при
  `маска & 0x80` и операции распознавания.

## Команды, которые HAL действительно шлёт

| № | имя | когда | тело |
|---|---|---|---|
| 1000 | `DETECT_SENSOR` | открытие | 544 байта |
| 1001 | `INIT` | открытие | 344 байта (нулевое при отсутствии кеша OTP) |
| 1004 | `DOWNLOAD_CFG` | условно | пропускается, если признак в ответе 1000 `+100` не ноль |
| 1005 | `INIT_FINISHED` | после 1001 | 100 байт |
| 1010 | `AUTHENTICATE` | распознавание | 120 байт; группа, вызов, −1 |
| 1014 | `SET_ACTIVE_GROUP` | перед 1010 | 100 байт |
| 1016 | `COMMAND` (обработка события) | после края | **`0x4FFA8`** байт, тело общее |
| 1086 | `AUTHENTICATE_FINISH` | после успеха | 120 байт из полей ответа |
| 1012 | `SAVE` | после 1086, если `save_flag` | 108 байт: группа `+0x60`, `finger_id` `+100` |
| 1085 | `UPDATE_STITCH` | после 1086, если `update_stitch_flag` | 104 байта: те же два поля |
| 1013 | `REMOVE` | удаление шаблона | — |
| 1090 | `LOCKOUT` | сброс блокировки | — |
| 1091 | `PAUSE_ENROLL` | пауза записи | — |
| 1111 | `INIT_MODEL` (фильтр) | серия 46 | `0xC3568` байт |
| 1064/1102/1103 | виды «снимок/касание/…» | по маске | — |

## Тело события 1016 ✅BIN (`irq.rs`)

* Размер `0x4FFA8`; поле-ступень `+0x4FF9C` = `1` при старте;
* первые поля `+0x4FD65 = 0x02000000`, `+0x4FD94 = 0x200`;
* после ответа тело **сохраняется** и снова уходит в следующем `1016`
  (`@0x5cbac–0x5cc24` — заполнение, `@0x5ccec–0x5cd44` — повтор);
* предел длины у шима: `DLINA` поднимается до `0x4FFA8` (`fix_dlina`).

## Условные шаги открытия ✅BIN

* После `INIT_FINISHED` сток зовёт `@0x60ae0`: если слово конфигурации `+208`
  (взятое из ответа `DETECT_SENSOR` с `+96`) не ноль — маскирует IRQ и шлёт
  `1016` с нулевым телом и `+0x4FF9C = 2`. ✅MSR На планшете слово равно 1.
* Полное открытие HAL: `GET_FW_INFO`, затем `RESET` (`GF_IOC_RESET 0x6702`),
  и только после этого обнаружение датчика.

## Требования к Rust

1. Порядок: открытие → питание/сброс → `DETECT_SENSOR` → `INIT` →
   (условно `1016`) → `INIT_FINISHED` → модель → группа.
2. Ровно одно событие на край; после результата — `1086` (только после
   успеха, один раз).
3. Разделять маску (`+96`) и операцию (`+100`); не считать «продолжением»
   шаг ответа, если он пришёл с маской без `0x80`.
4. Проверять оба статуса ответа.
5. После `1086` — флаги `+0x74`/`+0x75` → `1012`/`1085`.
