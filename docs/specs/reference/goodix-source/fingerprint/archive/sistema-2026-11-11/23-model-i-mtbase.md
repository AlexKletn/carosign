# 23 — Сток: модельный путь (1111), MT_BASE (1110), дампы (1089)

## 23.1 `hal_milan_init_model` @`0x163324` — `1111 INIT_MODEL`

```
if (cVar1 == 0) …   /* условие первого байта не названо в декомпиляции —
                       это не разобрано, пометка отдельно */
malloc(0xc3568)
условие: (config[0x1ad] != 0) && (config[0x1b2] != 0)
memset(body, 0)
body[0xc3564] = 0                 /* вид модели */
FUN_001635c8(body + 0x60, body + 0xc3560, 0)   /* выбор и подготовка весов */
invoke_command(1111, body, 0xc3568)
если config[+0x184] != 0 → повторный путь (повторное заполнение тем же телом)
```

Тело:

| смещение | что |
|---|---|
| `+0x60` | начало весов (в нашем разборе — `DLWeightLightDubaiB16BIT`) |
| `+0xc3560` | число слов (у стока `0x238ed`, проверено ✅BIN) |
| `+0xc3564` | вид модели (`0` у основного пути) |

⚠️ Наше ранее записанное «веса с `+96`» — это `+0x60`. Одно и то же.
⚠️ Число слов **кладёт сама функция подготовки** (`FUN_001635c8`), а не
константа: `0x238ed` лишь частный случай для серии 46.

## 23.2 `gf_hal_mt_base_load_mt_base_to_ta` @`0x13c984` — `1110 MT_BASE`

```
malloc(0x73e8)
memset 0
invoke_command(1110, body, 0x73e8)
```

Вызывается **только** при `config[0x1b0] != 0` (из `gf_hal_reinit` и из
`hal_milan_init_model`-пути). Рядом функция читает `MT_BASE` из файла —
значит на планшете база либо лежит в файле, либо приходит в ответе.
⚠️ Это второй большой буфер после модели (29 672 байта) — при переносе
держать запас в DMA.

## 23.3 `gf_hal_milan_dump_chip_init_data` @`0x13d278` — `1089 GET_DEV_INFO`

```
если (кто-то) и gf_is_dump_bigdata_enabled()
malloc(0x1578)
memset 0
invoke_command(1089, body, 0x1578)
```

⚠️ Тело **5496 байт**. Шлётся только при включённой отладке больших
данных: в рабочем пути его нет.

## 23.4 Что из этого — опорное, а что — отладка

| команда | в рабочем пути? | зачем |
|---|---|---|
| `1111` | **да**, обязательна для серии 46 | веса фильтра |
| `1110` | по признаку `config[0x1b0]` | база для чувствительного узла |
| `1089` | нет (отладка) | сведения о кристалле |
| `1064`/`1102`/`1103` | нет (испытательные) | калибровка/стабильность |
| `1071`–`1073` | по признаку навигации | жест |

## 23.5 Сверка с нашим прежним разбором

* ✅ Тело `1111` `0xc3568`, веса с `+0x60`, число слов в `+0xc3560`, вид в
  `+0xc3564` — совпадает с `goodix.rs`.
* ⚠️ Условие повтора `config[+0x184]` (другая модель) — в нашем описании
  отсутствовало.
* ⚠️ `1110` в нашем описании был «?» — теперь 29 672 байта.
