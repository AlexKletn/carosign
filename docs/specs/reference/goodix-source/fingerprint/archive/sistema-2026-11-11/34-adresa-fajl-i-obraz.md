# 34 — Где начинается `.text` и почему таблицы «не читаются»

Короткая, но важная запись: **ошибка не в таблицах, а в адресах**.

## 34.1 Две системы адресов в одном образе ✅BIN

`readelf -SW libgf_hal.so`:

```
[10] .text   виртуальный адрес 0x0161a0   смещение в файле 0x0161a0
[11] .rodata виртуальный адрес 0x09ee80   смещение в файле 0x09ee80
[21] .data   виртуальный адрес 0x0d1000   смещение в файле 0x0c1000
```

`libgf_hal.so` — **PIE** с загрузкой по `0x10000`-кратным сегментам;
`.text` и `.rodata` в файле лежат **по тем же смещениям**, что и их
виртуальные адреса, а `.data` — **на `0x10000` раньше**.

⚠️ Отсюда два правила:

* **для `.text`/`.rodata`** адрес = файловое смещение (0x161a0 ≠ 0x261a0!);
* **для `.data`** адрес = файловое смещение + `0x10000` (именно так читались
  таблицы имён в [25](25-imena-svereno.md) — и они прочитались).

В [33](33-tablicy-perehodov.md) я читал `.text` с поправкой `+0x10000`
(то есть вообще вне кода) — потому и получил «числа вместо команд».
`objdump` на `0x1635c8` по этой причине выдавал пустоту.

## 34.2 Где на самом деле `hal_milan_select_model`

`nm -D` даёт `0x1635c8` — это **виртуальный** адрес. В файле функция лежит
по **`0x1535c8`**. То же для `hal_milan_init_model`: `0x163324` → файл
`0x153324`.

⚠️ **Все адреса, прочитанные в разделах 13, 16, 17, 22–23 из
декомпиляции Ghidra, — виртуальные** (+`0x10000` к файлу). Для чтения
`objdump` по файлу их надо уменьшать на `0x10000`; для `.data` — наоборот,
увеличивать.

## 34.4 Как читать правильно

```sh
# функция (виртуальный адрес 0x1635c8) лежит в файле по 0x1535c8
dd if=libgf_hal.so of=/tmp/f.bin bs=1 skip=$((0x1535c8)) count=$((0x1550c8-0x1535c8))
aarch64-linux-gnu-objdump -D -b binary -m aarch64 --adjust-vma=0x1635c8 /tmp/f.bin
```

⚠️ `--adjust-vma` — **виртуальный** адрес, чтобы цели переходов совпадали с
адресами из `nm`/декомпиляции; а `skip` — **файловое** смещение. Это разные
числа на `0x10000`.

## 34.5 Урок

Тот же класс ошибки, что «сверять смещения полей, а не длину»
(ленточная памятка): **число верное, но не в той системе отсчёта**.
Проверка простая: если по адресу в `.text` получаются числа, а не команды —
значит сдвиг на `0x10000`.
