# Check 3: power, retries, netlink port

Заход 11 ноября, поздняя ночь. Проверял уже не описание, а **пробелы,
которые дают «работает до определённого места»**: чего сток делает
обязательно, а у нас этого нет или оно сделано иначе.

## Упущенное — найдено и дописано

### 1. Повтор обнаружения счётчиком `local_4c` ✅BIN

`gf_hal_open` @`0x1163f8`:

```c
local_4c = 4;                                 /* попыток */
do {
    memset(body, 0, 0x220);
    gf_hal_control_spi_clock(1);
    body[0x218] = local_4c;                   /* счётчик попытки! */
    rc = gf_ca_invoke_command(1, 1000, body, 0x220);
    gf_hal_control_spi_clock(0);
    if (!rc) break;
    local_4c--;
    if (!local_4c) break;
    gf_hal_reset_chip();
    usleep(5000);
} while (1);
```

⚠️ Тело `DETECT_SENSOR` — **544 байта, и в `+0x218` лежит счётчик попытки**
(4, 3, 2, 1). Наше `goodix.rs` шлёт `vec![0; 544]` — то есть **нулевой
счётчик**. Это не «вторая причина», но расхождение с стоком на первом же
шаге, и повтор обнаружения у нас не делается.

### 2. `g_hal_config` берётся из ответа `DETECT_SENSOR` ✅BIN

`gf_hal_open` после успешного `1000`:

```c
memcpy(g_hal_config, body + 0x60, 0x1b8);     /* 440 байт с +96 */
gf_hal_function_init(g_hal_function, config[+4]);   /* выбор поколения */
```

⚠️ **`config[0xd0]` = `body[0x100]`** — это то самое слово `+100`, которое
Rust уже читает как признак пропуска `DOWNLOAD_CFG` и начального `1016`.
Сходится ✅. Но `config[+4]` (!) — **второе требование**: по нему выбирается
таблица функций (Milan AN, Milan A, Oswego M, …). Наше `goodix.rs` таблицы
не выбирает вовсе — это **верно** лишь потому, что датчик Milan AN; при
другом кристалле путь разойдётся молча.

### 3. OTP-кеш — формат и CRC ✅BIN

`gf_hal_common_load_otp_info_from_sdcard` @`0x120e54`:

* файл `/data/media/0/gf_otp_info`, размер `0xc0` данных **+ 1 байт CRC8**;
* читается `0xc1` байт, если меньше — `0x438`; нет файла — `0x437`;
  CRC не сошёлся — `0x3f7`;
* CRC8: полином **`0x07`** (MSB-first), отражение входа/выхода, итог
  **дополняется** (`return ~crc`). Таблица лежит в `.rodata` @`0x1a095f`,
  первые байты `00 07 0e 09 1c 1b 12 15`.
* `save_otp_info_into_sdcard` @`0x121244` пишет данные и последний байт CRC.

⚠️ На планшете файла нет, поэтому `INIT` уходит с нулевым телом (как и у
нас). Но если файл однажды появится, Rust не поймёт его формат — теперь
понятно.

### 4. Порядок `gf_hal_device_enable` ✅BIN @`0x137478`

```c
pthread_create(gf_handle_thread);     /* обработчик событий */
ioctl(fd, GF_IOC_INIT, &route);       /* 0x80016700 → портид netlink */
pthread_create(gf_hal_netlink_recv);  /* приёмник событий */
ioctl(fd, GF_IOC_ENABLE_IRQ);         /* 0x6703 */
```

⚠️ **Перед `GF_IOC_INIT` у стока уже работает приёмник? Нет** — сначала
`GF_IOC_INIT`, потом приёмник, потом маска. Наш Rust делает `GF_IOC_INIT`
затем `ENABLE_IRQ` и только после этого ждёт — порядок отличается: у стока
приёмник заводится **до** маски. Исправление дешёвое, но обязательное.

### 5. Счётчики «вида» — `DAT_518e70/74/78` ✅BIN

В `gf_hal_milan_an_series_irq` (после `FUN_0015f880`) флаги
`(обработка ответа вида 1064 / 1102 / 1103)` ставятся **вне** условия
успеха, а по полю `+104` тела ответа. Это уже учтено в `irq.rs` (`operator`).

## Что проверено ещё раз и сошлось

* `1012`/`1085` — 108/104, флаги `+0x74`/`+0x75` (см. заход 2).
* `1111` — `0xc3568`, `0x238ed` слов — совпадает.
* Шим: `DLINA` → `0x4FFA8`, адрес в `+0`, 32-битное слово — совпадает.
* Заголовок: `cmd_id@32`, длина `@36`, номер пакета `@8`, время `@16` —
  наш `encode` пишет `@8`, `@12=1`, `@16`, `@32`, `@36`; сток эти же поля,
  но `@12` — `1` (наш подход совпадает).

## Внесено в код этим заходом

1. `goodix.rs`: `DETECT_ATTEMPTS = 4`, `Command::DetectRetry(u8)`, поле
   `body[0x218] = попытка`, `Transport::reset_sensor()` (по умолчанию —
   отказ с текстом, а не тишина), повтор `DETECT_SENSOR` с обратным отсчётом,
   как `gf_hal_open` @`0x1163f8`. Испытание
   `detect_retries_with_attempt_counter_like_stock` (последовательность
   `[4, 3, 2]` при двух отказах, сброс между ними).
2. `irq_device.rs`: проверка, что netlink-сокет привязан **до** включения
   маски (порядок как в `gf_hal_device_enable`): событий иначе не будет,
   и отказ теперь названный.
3. Проверки: 35 + 4 теста, Clippy чист, сборка aarch64.

## Чего не хватает, чтобы «пробелов не осталось» (честный список)

| что | почему это пробел | чем закрывать |
|---|---|---|
| **запись (enroll)** | Rust не умеет вовсе | перенос `1006 → 1007 → 1012 → 1008` |
| **выбор поколения по `config[+4]`** | работает только потому, что кристалл Milan AN | отказ, а не «тишина», при другом |
| **`0x405` → повтор `fw_cfg`** | Rust не повторяет | цикл из `FUN_0015f78c` |
| **`1003 DOWNLOAD_FW`** | нужна только при отказе | переносить при первом отказе |
| **OTP-кеш** | файла нет — сейчас не влияет | CRC8 известен, формат `0xc0+1` известен |
| **приёмник событий в отдельном потоке** | Rust читает в цикле; сток — поток | проверить на железе, теряется ли событие при долгом `1016` |
