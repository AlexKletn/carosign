разложить из `linux-rom/fingerprint/hal-harness/staging` (13 МиБ).

## Правка, которая внесена в клиент

✅ Двоичное `libgf_hal.so`:
- `@0x5fa20–0x5fb48` — главный обработчик берёт операцию `+100`, вычитает `4`
  и прыгает по таблице `@0xa8a18`. Случаи `0…4` — операции `4…8`; всё остальное
  (в том числе наша операция `1`) ничего не делает.
- `@0x5f8cc–0x5f948` — флаги «вид команды совпал» для `1064`, `1102`, `1103`.
- `@0x5ccec–0x5cd44` — повтор области тела, пока шаг равен `4`.

Отсюда правка: ответ с шагом `4` (`Image`) или `5` (`PostImage`) считается
просьбой о продолжении — следующий `1016` сразу, с тем же телом. Добавлена
ступень состояния `AwaitingContinuation`, `await_next_interrupt` принимает
и `HandlingInterrupt`.

Проверки: `cargo test -p spinel-fingerprint` — 33 + 4, Clippy `-D warnings`,
сборка `aarch64-unknown-linux-gnu`.

## Что осталось нерешённым

1. **Маску правило не различает.** На замере служебный `[7]` при маске `0x0`
   и операции `Authentication` тоже увёл в ожидание края. Нужно решить по
   стоку, что считать продолжением для такой маски.
2. **Почему после первого касания серия не идёт.** Сток на первое событие
   (`[2]`, операция `1`) не делает ничего и ждёт край — значит край должен
   прийти от датчика. Что держит датчик в неподвижности после первого
   `1016` — не разобрано.
3. **Очередь отстаёт от сеанса** («вру» — ответ на позапрошлое нажатие).
   Сеанс должен считать события с момента взведения, а не брать первое
   попавшееся.
4. **Сравнение со стоком** — прогнать `auth-probe` через HAL как эталон на той
   же серии событий, а не искать команды перебором.

## Как продолжать следующий сеанс

```sh
# эталон HAL (после перезапуска /tmp пуст)
tar -C linux-rom/fingerprint/hal-harness/staging -cf - . \
  | ssh root@<адрес> 'mkdir -p /tmp/fphal && tar -C /tmp/fphal -xf -'

# ключ шима, если нужен
scp linux-rom/fingerprint/qseecom-shim/spinel_qseecom.ko \
  root@<адрес>:/root/spinel-fingerprint-rust-stage/spinel_qseecom-new.ko

# прямой путь
ssh root@<адрес> 'cd /root/spinel-fingerprint-rust-stage && \
  ./spinel-fingerprint --native-handle-irq filter-dubaib16.bin'
```

⚠️ Кнопка `reboot` из SSH на этом планшете один раз уже закончилась молчанием
после перезапуска (10 ноября, 21:3x) — адрес потом сменился на `.173`, и там
всё поднялось. Перед следующими действиями — искать планшет
`tools/spinel-najti-obshodom.sh`, а не держаться за прежний адрес.

## Что выяснено эталоном (22:1x, `192.168.1.173`)

✅ `auth-probe` через штатный HAL: `auth_ok`, `match_score=35`; после результата
HAL прочитал устройство ещё три раза подряд, и только потом события стихли.
**Сток не ждёт край после первого `1016` — он читает дальше.** Подробно —
[IRQ-POSLE-VZVEDENIYA.md](10-event-measurements.md).

✅ Модули поднимаются скриптом `tools/spinel-fp-moduli.sh` — порядок
`proba → шим → датчик`, иначе шим валит `Unknown symbol`.
Эталон HAL после перезапуска разложен в `/tmp/fphal` (вместе с `auth-probe`).
