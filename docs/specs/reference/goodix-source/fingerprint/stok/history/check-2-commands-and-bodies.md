## Дописано (чего не было)

1. **Запись отпечатка:** `1006 PRE_ENROLL` (тело `0xb0`, из
   `gf_hal_common_pre_enroll` @`0x11be8c` и `gf_hal_common_enroll`
   @`0x11d05c`), `1008 POST_ENROLL`, `1007 ENROLL`. В спецификации их не
   было — а Rust обязан уметь запись, чтобы шаблон вообще появился.
2. **`1005 INIT_FINISHED`** — `gf_hal_init_finished` @`0x11b7bc` шлёт `1005`
   (`0x3ed`).
3. **Таблица слотов `g_hal_function`** — [15](../../archive/sistema-2026-11-11/15-tablica-hal-function.md):
   `+0xd8` = `gf_hal_invoke_command`, `+0x58` = `gf_hal_set_active_group`
   (и `1014` уходит только когда слот пуст), `+0x70` = `gf_hal_irq`.
4. **Тела по адресам:** `1110 MT_BASE` — `0x73e8`, `1089 GET_DEV_INFO` —
   `0x1578`, `1103` — `0xee6a8` (гигантское, проверить при переносе).

## Что это меняет для дальнейших заходов

1. **Расчётный порядок записи:** `1014` → `1006` → `1010` (режим записи) →
   `1016` … → `1012` при `samples_remaining = 0` → `1008`. В Rust из этого
   есть только `1010`/`1016`/`1012`.
2. **Тело `1013` (192 байта)** — при удалении шаблона. Не переносить по памяти.
3. **Осторожно с `0x435`** (команда с телом `0x60`, отправитель
   `FUN_00159fe8`): по перечню это ни `1077`, ни `1103` — **номер требует
   одной сверки с `PERECHNI.txt`**, прежде чем переносить. `0x440`
   (`FUN_00151400`, тело `0xee6a8`) и `0x441` `GET_DEV_INFO` (`0x1578`) —
   служебные/тестовые, в обычный путь не входят.
5. Полная последовательность по шагам — [16](../../archive/sistema-2026-11-11/16-posledovatelnost.md).
