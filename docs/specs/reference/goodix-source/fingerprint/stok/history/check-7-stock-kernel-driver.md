# Check 7: stock kernel driver

Заход 11 ноября. По указанию «драйвер ядра Android посмотри в стоковых ром,
должен быть там» — нашёлся.

## Где он лежит

`source_artifacts/dumps/tb371fc-stock/boot_unpacked/kernel` — стоковое
ядро, 37,6 МБ. Таблица имён разобрана `tools/spinel-kallsyms.py`
(121 415 имён). Проверено: `gf_power_on`, `gf_hw_reset`, `gf_power_off`,
`gf_irq`, `gf_ioctl`, `gf_probe`, `gf_parse_dts` — все на месте.

⚠️ Это **тот же приём, что уже применялся** к тачу и камерам
(`tools/spinel-kallsyms.py` + `objdump -b binary`). Имена нашлись сразу —
значит приём работает и здесь.

## Что прочитано (✅BIN)

| функция | адрес | что даёт |
|---|---|---|
| `gf_power_on` | `0xa709c8` | пауза → рельса 3 000 000 мкВ → 15 → RST `1` → 25 → RST `0` → 6 |
| `gf_hw_reset` | `0xa70c48` | RST `1 → 0 → 50 880 → 1` (и пауза `ms` после) |
| `gf_power_off` | `0xa70bf8` | `regulator_disable` + 1 пауза |
| `gf_ioctl` | `0xa6f8d0` | только `cmd & 0xff00 == 0x6700`, иначе `-ENOTTY` |
| `gf_irq` | `0xa70280` | `pm_wakeup_ws_event` → `sendnlmsg` |
| `gf_parse_dts` | `0xa70818` | GPIO сброса и IRQ, `regulator_get(vdd)` |

Дерево (`dtbo-02.dts`, `fragment@73`): вывод **85** — сброс, **23** — IRQ,
рельса **`pm8150a_l11`**. Совпадает с нашим деревом
(`sm8250-lenovo-spinel.dts`: `reset-gpios = <&tlmm 85 …>`,
`irq-gpios = <&tlmm 23 …>`, `vreg_l11c_3p3`).

## Что это исправило

1. **Комментарий в нашем дереве был неверен.** Там стояло «сброс деятелен
   низким: `gf_hw_reset` роняет линию, ждёт 3 мс и поднимает». По двоичному
   стока: `gf_hw_reset` пишет **RAW** `1 → 0 → пауза → 1`, а не «низкий
   3 мс». Исправлено в `sm8250-lenovo-spinel.dts`.
2. **Наш C делает другой фронт и другие паузы.** `spinel_fp_hw_reset`:
   `0 → 10 мс → 1 → 3 мс → 0`. `spinel_fp_razbudit`: `msleep(40)` →
   рельса → `10 мс` → `1 → 3 мс → 0` → `10 мс`.
   Сток: `41 → рельса → 15 → 1 → 25 → 0 → 6` (единицы `__const_udelay`).
3. **Открытие ioctl'а**: все команды — `0x6700…0x670b`, ровно те, что мы
   шлём.

## Чего это не дало

Единица `0x8958` (35 160) — множитель `__const_udelay`, а **не** милли-
секунды: без `HZ` стокового ядра число в мс не переводится. Доказаны
**порядок и отношения** (`41 : 15 : 25 : 6`, `50 880`), а абсолютные
миллисекунды — нет. ⚠️ Поэтому подставлять «41 мс» нельзя, это будет
новая догадка взамен старой.
