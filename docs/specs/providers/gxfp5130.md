# GXFP5130 (ChicagoHS) — первый software matching backend

## Из исходного проекта

Собственные `gxfp-driver`/`gxfp-stream`, кадры 80×64, работа с PSK/TLS sensor session; собственный matching (NCC, phase, embedding/hybrid), `gxfp-authd`, PAM и UI, encrypted redb templates, отдельное TPM2 sealing для keyring secrets. Документ `reference/gxfp_user_facing.md` описывает **пользовательский слой**, не низкоуровневый wire сенсора.

## Что переносим

- `CaptureSession`: probe/activate, аппаратные циклы, capture events — в GXFP provider.
- `Matcher`: configurable NCC/phase/embed/hybrid — внутри worker, не в Core.
- `TemplateFormat`: явная версия, набор видов/composite, формат миграции.
- `Storage`: port для зашифрованных шаблонов, compatible provider state.
- `EnrollmentProgress`: нормализованные события `MoveFinger`, `RetryRequired`, coverage без раскрытия кадров.

## Что не переносим без изменений

- Одно соединение = один AuthRequest, bincode — заменяет общий client/provider протокол.
- `SO_PEERCRED` + user == authorization для enrollment — новый authority grant + reauth.
- Release GNOME Keyring password как часть `Verify` — отдельная защищённая integrations layer.
- Глобальный abstract datagram overlay — новые per-operation scoped subscriptions.
- Числа threshold/coverage/sweep остаются **провайдерскими** настройками, не политикой биометрического Core.

## Security class

Software matcher работает с изображениями и шаблонами в software trust boundary. Root-only keyfile сам по себе не создаёт hardware-sealed security. Требуются оценки FAR/FRR на достаточно репрезентативной выборке прежде чем позиционировать thresholds для широкого production. Нельзя подменять hardware evidence программным `Matched`.

## Нагрузки

OpenVINO/NPU и другие тяжёлые зависимости принадлежат отдельному package, допускаются optional features. Worker ограничивается memory/CPU/pids; network disabled по умолчанию. Чтобы избежать переплаты на IPC, кадры держатся внутри worker; public runtime не получает поток raw frames.

## Первая вертикальная реализация

Подключить новый `carosign.provider.v1` worker к текущему GXFP и проверить `discover → enroll → verify → remove → restart → recover` до переноса деталей systemd/PAM. Затем отдельно подключить PAM и GUI нового Linux service.
