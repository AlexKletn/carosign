# 26. `carosign.broker.v1` — mediated service protocol (normative v0.6.1)

This document defines the only v1.0 meaning of `FD_ROLE_MEDIATED_SERVICE`. It is **not** arbitrary access to Linux syscalls, ioctl, QSEE/RPMB or TA commands. The wire schema is [`broker.proto`](../../contracts/proto/carosign/broker/v1/broker.proto). The provider-worker CONTROL protocol still permits FDs **only** on `BindAuthenticator`. The mediated broker transport independently supports a single sealed-memfd per `Call` or `CallResult` since broker minor 1, under [32](32-v065-bulk-command-buffer.md).

## Socket and trust boundary

The hardware broker creates a private, connected `AF_UNIX/SOCK_SEQPACKET` socketpair. It attaches one end to an approved broker-issued resource claim; that end is delegated via `SCM_RIGHTS` as a `BindAuthenticator` slot with `FD_ROLE_MEDIATED_SERVICE`. Broker retains the other end and the authoritative binding `(lease_id, worker_instance, authenticator_id, device_epoch, resource_id, role)`. No generic filesystem path is exposed for provider connections. ResourceId and LeaseId in received bytes are not capabilities.

`carosign.broker.v1` is a separate IPC protocol over that socket: one protobuf frame per seqpacket, max 64 KiB, strict per-direction `frame_seq` starting 1, 16B nonzero request IDs on calls/results, at most one normal result per accepted call. Broker minor 1 permits exactly one FD when `external_body` is present on `Call`/`CallResult`; all other ancillary FDs prohibited. `ServiceReady(resource_id, schema_version)` must be sent before any Call; worker compares ID with BindAuthenticator. Broker closes/rejects on wrong identity/sequence/phase. Socket possession proves only the originally delegated endpoint; it **does not** override expiry/revocation of broker authorization.

## Operation registry

`Call.operation_ref` is a **16-byte broker-assigned identifier** for an installed, administrator-approved handler. The broker owns a registry mapping `(package, profile, resource_id, operation_ref)` to a **fixed, audited function** with a *typed request decoder*, maximum request/response sizes, side-effect classification, mandatory resource mode and a per-call authorization hook. The registry must be provisioned by trusted system policy and cannot be populated by worker text, manifest self-claims or arbitrary operations at runtime.

For each call, broker rechecks live worker, lease, resource binding, expiration, device epoch, method allowlist, input schema and operation-specific authorizations **before** invoking handler. Missing handler/schema/policy ⇒ `UNSUPPORTED`/`UNAUTHORIZED` (typed error), never raw passthrough. Broker must also enforce operation-specific rate limits/deadlines. Host-side raw `invoke_any_ioctl` or `invoke_any_ta` is not part of this contract. The operation ref does **not** authorize arbitrary ciphertext or arbitrary TA commands: each handler accepts only its audited typed arguments.

For a handler classified as `MayMutatePersistent`, `Call.operation_id`, `.mutation_id` and `.command_id` are each 16 nonzero bytes, and the broker **must** consult a trusted, read-only `DispatchAuthorizationPort` to verify the durable `DISPATCH_ARMED` record binds this exact operation/command/mutation to worker/lease/epoch. This check is in addition to per-call policy validation; worker-provided ID bytes alone confer no rights. One potentially mutating broker call is permitted for the armed provider command; multi-call mutation sequences must be encapsulated in an audited trusted handler or introduced through a separately reviewed protocol extension. Never retry an unknown call across process failure. For nonmutating operations `mutation_id` and `command_id` are empty; `operation_id` is required unless a separately approved read-only probe. This is not a hardware driver specification.

The `payload` is opaque to generic broker framing, **not** to the selected trusted handler: its schema and semantics are part of an independently versioned hardware-specific service contract, installed and audited before use. No such Goodix QSEE command schema or handler list is established in this generic package. An implementation agent cannot invent them; report `ARCHITECTURE_BLOCKER` for unsupported hardware operation. Maximum `Call.payload` and response bytes = 32768 each; network access is not implied. A broker-mediated mutation must additionally observe Runtime's durable `DispatchArmed` fence; simply issuing a broker Call cannot bypass mutation journaling.

## Cancellation and failure

A provider `RequestCancel` does not automatically cancel a broker call or underlying hardware operation. The broker rejects further calls once lease revoked, but an in-flight call may complete late; late responses are fenced by worker instance + device epoch and must not become success of a cancelled operation. Broker crash, disconnect or unknown hardware effect ⇒ device `Uncertain` and, if mutating call had been armed, `NeedsReconciliation`. Recovery is by independent verification, never blind replay.

## FD validation

`FdSlot.resource_id` must match the resource bound to the delegated endpoint. For the other roles: DEVICE is an approved broker-opened handle (not an arbitrary path); EVENT an approved eventfd; CONFIG an immutable sealed memfd. All FD slots are checked against broker records and their actual handle types. Unknown, extra, missing or duplicate slots without explicit grant fail the whole Bind. No ancillary FD on broker messages except one verified sealed-memfd accompanying `Call`/`CallResult.external_body` in negotiated minor 1. See [32](32-v065-bulk-command-buffer.md). See [09](09-device-and-broker.md), [20](20-protobuf-wire-validation.md), [25](25-v061-conflict-resolutions.md).

### v0.6.5 broker minor 1 boundary

`ServiceReady`'s **envelope** `major=1, minor=1` is the broker announcement. A worker accepting it responds with `Call` minor 1; a worker unable to support minor 1 MUST close/decline an external-body-required resource before any call. This is a one-sided version announcement, **not** an invented symmetric Hello/Initialize handshake. The trusted broker rejects minor 0 `Call.external_body` and any mismatch to the announced minor. The normal `Call.payload` stays typed and bounded; only `Call`/`CallResult` with `external_body` may each carry exactly one sealed-memfd FD. The `ServiceReady.service_schema` separately selects the audited handler schema and does not replace protocol minor or grant authority.
