# 01. Назначение, границы, принципы

## Потребитель и ценность

Linux-пользователь получает единый системный API биометрии. Разработчик аппаратной интеграции поставляет отдельный пакет `Provider`, реализованный на любом языке. Интегратор Veles использует тот же доменный контракт, не импортируя Linux PAM и не дублируя подсистему безопасности Veles.

## Входит в продукт

- Registry биометрических устройств/аутентификаторов и регистраций.
- Управление длительными операциями и ресурсами устройства.
- Enrollment, verification, identification (только у поддерживающих провайдеров), removal, enumeration, reconciliation.
- Журнал мутаций и recovery после неоднозначного исхода.
- Платформенные extension points: identity authority, authorization, evidence, storage, secure environment, interaction.
- Независимо устанавливаемые исполняемые providers, версионируемый wire ABI, Provider Manager/Supervisor.
- Linux service `carosignd`, клиентские инструменты, PAM, опциональные D-Bus/fprintd compatibility.
- Набор проверок совместимости провайдеров и спецификации протокола.

## Не входит

- Универсальный менеджер сессий ОС и политика входа/разблокировки.
- Самостоятельная глобальная служба секретов или аппаратная криптосистема.
- Явь, Поводник, Uzel, cgroup-принципалы Veles.
- Общедоступный экспорт изображений пальцев и биометрических шаблонов.
- Обязательное переписывание существующих драйверов libfprint.
- Обязательная аппаратная гарантия для каждого поддерживаемого аутентификатора.

## Жёсткие инварианты

- **P-01:** публичные клиенты не взаимодействуют с hardware provider напрямую.
- **P-02:** `Matched` от worker != `AcceptedFactor` от доверенного verifier != системное `Authorized`.
- **P-03:** произвольный `UID`, `SubjectRef`, `OperationId` или `GrantId` не является capability.
- **P-04:** будущие mutating commands не отправляются до durable intent.
- **P-05:** запрос отмены != доказательство аппаратного quiesce.
- **P-06:** worker restart != device recovery.
- **P-07:** отсутствие способности проверить outcome мутации означает `NeedsReconciliation`, не выдуманный success.
- **P-08:** Software evidence нельзя объявить аппаратным.
- **P-09:** при отсутствии hardware proof предоставляются только гарантии явно доверенной программной конфигурации.
- **P-10:** device/profile/platform detection не должна сама выполнять изменяющие аппаратные действия.
- **P-11:** отдельный provider может быть обновлён/удалён без изменения Core; enrollment не удаляется автоматически.
- **P-12:** спецификация API не зависит от языка программирования и Rust ABI.

## Первые поддерживаемые модальности

Fingerprint — единственная обязательная модальность первой версии. `Modality` — расширяемый тип, но пока не вводим фиктивную поддержку лица/радужки. Каждая возможность привязана к конкретному backend и его проверенному поведению.

## Non-functional expectations

Fail-closed при нарушении контекста, ограничения размеров и ресурсов, прозрачная диагностика без сырого отпечатка, отсутствие скрытой эскалации доверия, стабильный API между версиями, поддержка альтернативного способа входа при отказе биометрии.
