# Ручное включение PAM на Arch Linux

В каталоге `packaging/arch/pam/` находятся примеры для `sudo` и для входа
через `login`. Они соответствуют конфигурации, наблюдавшейся на тестовом
планшете; перед использованием нужно сверить их со своими файлами
`/etc/pam.d/sudo`, `/etc/pam.d/login`, `system-local-login`, `system-login`
и `system-auth` и сохранить все дополнительные правила своей системы.
Не заменяйте этими примерами общие файлы `system-auth` и `system-login`.

Моковый провайдер способен выдать искусственный успешный результат: любой,
кто управляет моком, сможет использовать его для входа и `sudo` без пароля.
Включайте его только для испытаний и отключайте по их завершении.

1. Оставьте открытым сеанс администратора и предусмотрите способ восстановления
   доступа. Сохраните копии обоих исходных файлов за пределами `/etc/pam.d`.
2. Убедитесь, что установлен `pam_carosign.so`, работает платформа и у
   пользователя настроен проверяемый провайдер. Сначала испытайте только один
   из двух файлов, затем второй; устанавливайте конфигурации с владельцем
   root и правами `0644`.
3. Проверьте успешную биометрическую проверку и вход по паролю при отключённом
   провайдере. Отдельно проверьте отказ при неверном пароле и соблюдение
   действующей блокировки `faillock`.
4. При проблеме восстановите соответствующий сохранённый файл из открытого
   административного сеанса. Обновления PAM-пакетов могут менять штатные
   цепочки; после обновления повторно сверяйте примеры со своей конфигурацией.

`preauth` проверяет действующую блокировку перед биометрией. При успешной
биометрии `authsucc` сбрасывает счётчик неудачных попыток. Подтверждённое
несовпадение учитывается через `authfail`; отмена, отсутствие образца и отказ
службы счётчик не увеличивают. Затем выполняется штатная парольная цепочка,
которая сама ведёт учёт попыток. Биометрические и парольные ошибки используют
общую блокировку; неверный пароль после несовпадения может добавить ещё одну
ошибку. Номер перехода `default=3` привязан к трём
следующим правилам и при их изменении должен быть пересмотрен. Проверка учётной
записи и открытие сеанса остаются штатными. В примере `login` проверки оболочки
и `nologin` перед биометрией повторяют правила текущего `system-login`; при
изменении последнего необходимо синхронизировать и их.

Изолированная проверка порядка ветвей через системный libpam:
`sh tools/test-pam-sudo-stack.sh`. Она включает настоящий `pam_faillock` с
отдельным временным каталогом и не проверяет установленный провайдер,
действительный файл блокировок или вход на конкретной машине.

Для однострочного интерфейса `sudo` нужно разрешить сообщения PAM: штатная
настройка sudo `pam_silent` их подавляет. Пример настройки находится в
`packaging/arch/pam/sudoers-carosign`; проверьте его через
`visudo -c -f` перед установкой в `/etc/sudoers.d/` с правами `0440`, затем
проверьте всю конфигурацию `visudo -c`. Настройка действует и на сообщения
других PAM-модулей sudo. Для восстановления удалите этот файл.
