# Набор для проверки сборки

## Проверочный пакет для Arch Linux ARM

Отдельно подготовлен дорелизный pacman-пакет с названием
`carosign-preview`, предназначенный для проверки упаковки на
изолированном стенде. Сборка выполняется только на хозяине:

```sh
sh tools/build-arch-preview.sh /абсолютный/путь/к/новому-пакету.pkg.tar.zst
pacman -Qip /абсолютный/путь/к/новому-пакету.pkg.tar.zst
```

Скрипт использует кросс-сборку, указанную ниже, проверяет архитектуру каждого
ELF и метаданные пакета. Рецепт находится в `packaging/arch-preview/PKGBUILD`.
Пакет не включает службы, не меняет `/etc/pam.d`, не создаёт базу и не
устанавливает доверенные ключи. Два включённых unit-файла статические, без
`[Install]`, и служат только макетами; они не превращают демоны в рабочие
системные службы. Пакет не является первым выпуском и не предназначен для
входа в работающую систему.

На текущем хозяине две последовательные сборки дали побайтно одинаковые
пакеты. Рабочий каталог фиксирован на пользователя, потому что makepkg
записывает путь сборки в `.BUILDINFO`; при занятом каталоге сборка отказывает
и не перезаписывает его. Это не доказывает воспроизводимость на других машинах,
с другим UID, компилятором или окружением. Совместимость библиотек с целевой
системой, установка с разрешением зависимостей и запуск в чистой целевой
системе не проверены.

На хозяине пакет установлен и удалён `pacman` в отдельном пустом дереве через
`fakeroot`, без проверки зависимостей и подписи. Проверено отсутствие
`etc/pam.d` и включённых unit; удаление убрало файлы программы. Это проверка
упаковки и базы pacman, а не проверка зависимостей, подписи или запуска на
планшете.

## Проверочный архив

Описанный ниже архив **не установочный пакет и не готовый выпуск**. Он не создаёт системных
служб, не изменяет конфигурацию PAM и не устанавливает доверенные ключи.
Демон и посредник пока не работают как штатный состав, а PAM-модуль не
выполняет успешную биометрическую проверку. Не подключайте его к входу.

На машине сборки, с установленными Rust, Cargo, `protoc` и локальным кешем
зависимостей, из каталога проекта:

```sh
./tools/build-review-bundle.sh /абсолютный/путь/к/новому-review.tar
```

Команда собирает host release с `--locked --offline`; существующий архив не
перезаписывается. Для проверки состава распакуйте архив в отдельный пустой
каталог и выполните там `sha256sum -c SHA256SUMS`. Контрольные суммы проверяют
целостность после сборки, но не подтверждают подпись или происхождение.

Архив содержит `carosignd`, `carosign-broker`, `carosignctl`, отдельный
`carosign-fprintd-compat` и библиотеку `pam_carosign.so`, предназначенные
только для проверки. Приложенное описание D-Bus фиксирует интерфейс для будущей
реализации: исполняемый fprintd-адаптер отвечает на обнаружение пустым списком,
но работа с устройством и проверка не подключены. PAM-адаптер также не
выполняет положительную проверку. Архивирование
нормализует даты и владельцев; повторяемость самих двоичных файлов между
разными машинами, версиями компилятора и наборами зависимостей не подтверждена.
Для перекрёстной сборки на хозяине можно указать целевую тройку:

```sh
./tools/build-review-bundle.sh /абсолютный/путь/к/новому-review.tar --target aarch64-unknown-linux-gnu
```

На текущем хозяине подготовить параметры pkg-config и компоновщика можно
командой `CAROSIGN_SYSROOT=/абсолютный/путь/к/sysroot sh tools/build-review-aarch64.sh /абсолютный/путь/к/новому-review.tar`.
Она использует целевую libdbus из `source_artifacts/toolchains/.sysroot-aarch64`
и библиотеки C установленного aarch64-кросс-компилятора. Отдельный каталог
pkg-config не даёт компоновщику выбрать скрипт `libm` с абсолютными путями
хозяина. Нужны Rust-цель, кросс-компилятор и указанный sysroot. На хозяине
сборка и архитектура ELF проверены; совместимость смешанного набора библиотек
с целевой системой и исполнение на планшете не проверены. При ошибке сборки
архив не создаётся. Исполнять сборку на планшете нельзя.

Для проверки предполагаемой раскладки отдельно можно подготовить дерево в
существующем пустом каталоге на хозяине после сборки:

```sh
sh tools/stage-review-rootfs.sh /абсолютный/путь/к/пустому-каталогу aarch64-unknown-linux-gnu
cd /абсолютный/путь/к/пустому-каталогу
sha256sum -c SHA256SUMS
```

Это проверочная раскладка, не устанавливайте её в работающую систему: пути
пакета ещё не приняты, системных служб, установщика, политики и доверенных
ключей нет, PAM не настраивается. Изолированная проверка создания дерева не
является проверкой установки. На текущей сборке прямые динамические зависимости
четырёх исполняемых файлов — `libgcc_s.so.1` и `libc.so.6`, дополнительно для
fprintd-фасада — `libdbus-1.so.3`; PAM-библиотека напрямую зависит от
`libgcc_s.so.1` и `libc.so.6`. Исполняемые файлы требуют символы до `GLIBC_2.34`,
PAM-библиотека — до `GLIBC_2.17`. Это проверено по ELF на хозяине, не
подтверждает транзитивные зависимости и наличие совместимых библиотек в
целевой системе. Имеющийся `linux-rom/rootfs` — дополнение к системе, а не
полный корень с библиотеками для такой проверки.

Установочный пакет, системные службы, доверенные источники, положительный
сценарий PAM и инструкция безопасного включения будут подготовлены после
реализации и проверки штатного состава по спецификации первого выпуска.
# Статическая проверка зависимостей AArch64

Для отдельного дерева целевой системы можно проверить `PT_INTERP`, прямые и
транзитивные `DT_NEEDED` и требуемые версии символов, не выполняя код на
планшете. Проверка использует `aarch64-linux-gnu-readelf`; ссылки разрешаются
относительно указанного дерева, а не корня хозяина:

```sh
python3 tools/check-aarch64-deps.py /абсолютный/путь/к/rootfs \
  target/aarch64-unknown-linux-gnu/release/carosignd \
  target/aarch64-unknown-linux-gnu/release/carosign-broker \
  target/aarch64-unknown-linux-gnu/release/carosignctl \
  target/aarch64-unknown-linux-gnu/release/carosign-fprintd-compat \
  target/aarch64-unknown-linux-gnu/release/libpam_carosign.so
```

Код 0 означает лишь, что проверенные файлы и версии найдены в указанных
типовых каталогах. Динамический поиск вне них, `dlopen`, доверие к файлам,
ABI ядра и запуск службы эта проверка не подтверждает. `RPATH` и `RUNPATH`
вызывают отказ и требуют отдельной проверки. Неполный sysroot нельзя выдавать
за целевую систему: в имеющемся дереве toolchain библиотеки находятся в
`usr/lib`, но отсутствует путь загрузчика `/lib/ld-linux-aarch64.so.1`,
записанный в исполняемых файлах. Состояние работающей системы неизвестно.
