# CaroSign и публичный контракт fprintd

Аудит охватывает публичный D-Bus API fprintd для всех клиентов. Сигнатуры, ошибки, порядок сигналов и план проверки описаны в [аудите интерфейса](FPRINTD_WIRE_BASELINE.md).

## Что адаптер уже получает от CaroSign

| Возможность | Данные и операции платформы |
|---|---|
| Инвентарь | Идентификатор и поколение аутентификатора, доступность, модальность, поддерживаемые операции и режим взаимодействия. Число этапов регистрации передаётся, если известно. Провайдер может объявить отображаемое имя устройства. |
| Регистрации | Список записей пользователя на выбранном устройстве. Для каждой записи доступны метка, ссылка с поколением и признак необходимости сверки. |
| Регистрация и удаление | Запуск регистрации с меткой и опциональной заменой существующей записи. Удаление по точной ссылке на одну запись. Массовое удаление fprintd можно собрать из этих операций в адаптере. |
| Проверка | Проверка пользователя на выбранном аутентификаторе. Итог сообщает, принят ли фактор в рамках операции, либо возвращает отрицательный исход или ошибку. |
| Обратная связь | Подсказки, причины повторов, прогресс, количество принятых и требуемых образцов, если поставщик их сообщает. |
| Владение и права | Авторизация операции, выдача ресурса и его освобождение после подтверждённой уборки. Владение объектом по имени отправителя D-Bus и политика совместимости fprintd относятся к адаптеру. |

## Граница платформы и адаптера

- Платформа принимает точную ссылку `EnrollmentRef`, проверяет её в
  авторизованном наборе и возвращает подтверждённое совпадение исходному
  клиенту при наличии права раскрытия.
- Провайдер публикует наблюдаемое состояние захвата и причины отказа через
  общий контракт. Состояние применимо к пальцу, лицу, радужке и голосу.
- Адаптер сам связывает имена пальцев с регистрациями, переводит общие
  события в D-Bus-свойства и статусы fprintd и собирает массовое удаление
  из операций над отдельными регистрациями. PolicyKit проверяется для
  исходного отправителя на стороне адаптера.
- Общий контракт CaroSign развивается по потребностям платформы и её
  клиентов. Особенности fprintd реализуются в слое совместимости.

## Что CaroSign предоставляет сверх fprintd

- Общий договор для отпечатка, лица, радужки и голоса.
- Цель проверки как часть авторизации. Контракт различает вход, разблокировку, привилегированное действие, самопроверку и операцию с ключом.
- Именованные операции с идентификатором, сроком, фазой, нумерованными событиями, снимком состояния, итогом и запросом отмены.
- Состояние службы и агрегированный счётчик областей, ожидающих сверки. Поколение регистрации позволяет выявить попытку изменить устаревшую запись.
- Принятие биометрического фактора в рамках конкретного запроса. Решение о входе остаётся у системного потребителя, например PAM.
