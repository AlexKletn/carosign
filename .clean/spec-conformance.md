# Сверка реализации со спецификацией v0.6.6

19 ноября 2026 года. Сверка охватывает production-контур первого Linux-выпуска и его приёмку. Приоритет у [профиля 35](../docs/specs/engineering/implementation-v06/35-first-release-scope.md), затем у принятых уточнений по [правилам пакета](../docs/specs/engineering/implementation-v06/README.md). За wire-контракт приняты схемы из [contracts/proto](../contracts/proto/carosign). Проверка соответствия для Veles, поставляемых аппаратных провайдеров и всех строк общей матрицы отдельно не выполнялась.

## Подтверждённые расхождения

### 1. В рабочем запуске отсутствует доверенный источник исхода вооружённых изменений

D-02 теперь закрывается в рабочем контуре. После восстановления аппаратных
ограждений и до публикации сокета неотправленный `Prepared` без
сохранившегося ограждения этой операции устойчиво завершается как
`Completed(NoChange)`. Журнал и блокировка области обновляются одной
транзакцией. Старое аппаратное ограждение без идентификатора операции
запрещает автоматическое закрытие, поскольку его нельзя сопоставить с
конкретной мутацией. Проверка повторного открытия базы подтверждает
освобождение области и отсутствие изменений реестра.

Для D-05/D-06 добавлен путь `recover_guarded_with_evidence` с отдельным
источником независимой сверки и подтверждения уборки. Он сопоставляет
операцию, команду, работника, эпоху и весь снимок области со стойким планом.
При подтверждённом результате фиксирует `RegistryCommitted` или `NoChange`
и удерживает блокировку до отдельного подтверждения уборки. Тесты открывают
базу заново между этапами. Источник в штатном запуске пока отсутствует:
запрос `QUERY` к реальному провайдеру после перезапуска остаётся
зарезервированным. Отсутствующий или противоречивый исход оставляет область
заблокированной. [Спецификация 10](../docs/specs/engineering/implementation-v06/10-persistence-and-recovery.md#mutation-boundaries-and-exact-protocol),
[проводка восстановления](../crates/linux/carosignd/src/bootstrap.rs),
[транзакции](../crates/runtime/carosign-persistence/src/mutation_store/recover_armed.rs),
[проверка с тестовым источником](../crates/linux/carosignd/tests/service_boot_fixtures/armed_recovery.tests.rs).

Без живой истории журнал возвращает номер события 0. Для поиска по ID операции вне активного реестра схема v4 пока использует просмотр журнала. При выпадении номера из живого кольца `EVENT_GAP` переносит снимок и номер продолжения. Завершённая мутация наблюдается только после устойчивой фиксации. За пределами живой истории доступен снимок журнала без повтора событий. [Проводка](../crates/linux/carosignd/src/linux_service/observation_stream.rs), [проверка очереди](../crates/linux/carosignd/src/linux_service/operation_subscription.tests.rs) |

Изолированный тест требует, чтобы провайдер получил `Describe` после появления сокета до запроса клиента. ## Что остаётся подтвердить для выпуска

- Запуск штатного пакета aarch64 под systemd на целевой системе остаётся непроверенным. Нативный пакет x86-64 прошёл чистый запуск в QEMU. [Профиль 35, пункты 1–3 и 6](../docs/specs/engineering/implementation-v06/35-first-release-scope.md#условия-приёмки-первого-выпуска).
- На настоящем графическом клиенте и целевом провайдере требуется отдельный прогон отмены записи с повторной записью и проверкой без перезапуска. Сквозной мок подтверждает контракт платформы, включая удержание области при ошибке. Аппаратный сброс или откат конкретного провайдера этими тестами не измерялся. [Договор провайдера](../docs/specs/engineering/implementation-v06/06-provider-host-and-wire.md#транзакция-регистрации-и-явный-откат).
- Версию provider wire стоит уточнить в тексте пакета. Документы называют нижнюю границу live `minor >=3`, а текущие нормативные схемы и реализация для первого выпуска используют 1.4; реализация выставляет `MINOR_BASELINE = MINOR_MAX = 4`. Это разночтение описания поддержки, а не основание включать старую версию без договора. [Документ 06](../docs/specs/engineering/implementation-v06/06-provider-host-and-wire.md#L70), [границы кода](../crates/protocol/carosign-protocol/src/limits.rs#L61), [нормативная схема](../contracts/proto/carosign/provider/v1/provider.proto).

Срез обновлён после подключения `OpenSession`. Для обнаружения и прямого запуска использованы результаты прогонов `target/installed-discovered.log` и `target/installed-legacy-regression.log`. Регрессии прерываний и установки сеанса записаны в `target/discovery-interruption-regression.log` и `target/discovery-rendezvous-tests.log`. Проверки восстановления D-02 записаны в `target/recover-unarmed-boot.log`.
