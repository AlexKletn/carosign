# Тестовый провайдер биометрической платформы

Отдельный тестовый процесс для `carosign.provider.v1`; железо, шаблоны и аппаратные
гарантии не использует. Запускается с номером унаследованного дескриптора
`AF_UNIX/SOCK_SEQPACKET` первым аргументом. Не предназначен для установки как
боевой провайдер. Передача номера аргументом — соглашение тестового запуска;
платформенный проверенный запуск и его договор ещё не реализованы.

Пока реализованы `WorkerHello` v1.3, проверка `Initialize`, `Initialized`,
привязка синтетического аутентификатора без дескрипторов и `Describe`.
Поддерживается синтетическая проверка ограниченного набора регистраций:
после `CommandAck` она возвращает `NoUsableSample` (по умолчанию, аргумент
`no-sample`) либо `Matched` с первой разрешённой регистрацией (аргумент
`matched`). Для испытания независимого проверяющего аргумент `matched-token`
дополнительно возвращает синтетический токен из 32 байтов со значением 42.
Он не является доверенным доказательством и не даёт аппаратных гарантий.
Профили `seeded-no-sample` и `seeded-matched-token` предназначены для проверки
канала посредника: в памяти заранее задана одна синтетическая регистрация.
Они не проверяют регистрацию и не создают запись в хранилище платформы.
Все переданные привязки должны совпасть с состоянием мока по
субъекту, регистрации, поколению и непрозрачной ссылке. Совпадение требует
независимой оценки платформой и не означает аппаратной гарантии.
Корректный `QueryMutation` возвращает `QUERY_UNSUPPORTED` и не меняет состояние.
Регистрация, замена и удаление имитируются в памяти процесса с проверкой плановой
регистрации и старой привязки. Данные исчезают при завершении процесса; ответ
провайдера не означает устойчивую запись реестра. После завершения операции
отмена возвращает `CancelAlreadyTerminal`. Сценарий `pending-cancel` удерживает
проверку до запроса отмены и возвращает `CancelRequested`, затем
`VerifyCancelled`; он объявляет поддержку отмены только в этом сценарии.
Передача этой отмены через посредника и сценарии сбоев ещё не реализованы;
эта заготовка не подтверждает сквозную работоспособность платформы или
соответствие матрице W05/M-01…M-12.

Испытания отдельного процесса также проверяют отказ на повтор команды,
устаревшую эпоху и повтор кадра с прежним номером последовательности.

Проверка на машине разработчика: `cargo test --offline`.
# Управляемый по SSH испытательный мок

Сборка с `--features ssh-mock` запускается штатным supervisor с единственным
аргументом — номером файлового дескриптора. Этот вариант **не является
биометрической защитой**: администратор имитирует проверку командой. Не
используйте его как средство действительного входа и сохраните парольный PAM.

Непривилегированному UID/GID работника нужен принадлежащий ему каталог
`/var/lib/carosign-mock` с режимом `0700`: там хранятся фиктивные регистрации.
Root создаёт `/run/carosign-mock` с режимом `0755` и FIFO
`/run/carosign-mock/control` с владельцем root и режимом `0644`. Для
восстановления FIFO после загрузки можно использовать systemd-tmpfiles:

```text
d /run/carosign-mock 0755 root root -
p /run/carosign-mock/control 0644 root root -
```

Регистрация и удаление выполняются автоматически и не обращаются к железу.
Во время ожидающей проверки из root-сеанса SSH отправьте одну команду:

```sh
printf 'match\n' > /run/carosign-mock/control
printf 'no-match\n' > /run/carosign-mock/control
printf 'no-sample\n' > /run/carosign-mock/control
```

Без команды совпадение не выдаётся. Запись в FIFO ждёт читателя, поэтому
команду следует давать во время проверки. Отмена и разрыв соединения
прерывают ожидание. Удаление мока включает остановку его служб, удаление
профиля и tmpfiles-правила и удаление только созданного для него каталога
данных; к данным настоящего провайдера этот каталог не относится.
